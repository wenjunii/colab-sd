# ⚡ StreamDiffusion Remote TouchDesigner Bridge (`colab-sd`)

Real-time generative AI pipeline bridging **[StreamDiffusion](https://github.com/cumulo-autumn/StreamDiffusion)** (Stability AI SD-Turbo) running on a remote **Google Colab GPU** (T4 / L4 / A100) directly into local **TouchDesigner** via a secure, zero-config **Cloudflare Tunnel**.

## 🌟 Key Features

* **Cloud GPU Powered:** Run SD-Turbo on Colab Pro / Free tier (NVIDIA T4, L4, or A100) with zero local GPU load.
* **Two Operating Modes:**
  * **Text-to-Image (`txt2img`):** Continuous real-time synthesis (20–30 FPS on Colab GPU) dynamically driven by prompt and seed updates.
  * **Image-to-Image / Video-to-Video (`img2img`):** Real-time interactive stylization driven by TouchDesigner TOPs (external generators like `Noise TOP`, live webcam feed, or internal noise).
* **Interactive Denoise Strength Slider:** Dynamically shift between preserving subtle original geometry ($0.2$) and dramatic AI reinterpretation ($0.8+$) in real time.
* **Adaptive "Ping-Pong" Flow Control:** TouchDesigner sends frames immediately upon receipt of previous output, eliminating all socket buffer backlogs and reducing glass-to-glass latency to the physical minimum.
* **Live Telemetry HUD:** Displays remote Colab GPU inference time (ms), network round-trip ping (ms), and effective video FPS directly on the component UI.
* **Zero-Config Networking:** Uses Cloudflare Tunnels (`trycloudflare.com`) over secure WebSockets (`wss://`). No port forwarding, public IP, or VPN required.
* **Immune to OpenSSL / Buffer Limits:** Built-in **bidirectional chunking protocol** ($\le 4096$ bytes per packet) completely prevents TouchDesigner `WebSocket DAT` buffer overflows and `ssl3_write_bytes:bad length` exceptions.
* **Standalone Component (`.tox`):** Single, self-contained `StreamDiffusion_Remote.tox` ready to drag-and-drop into ANY TouchDesigner project.

## 🚀 Quick Start

### 1. Launch Server on Google Colab

1. Open [Google Colab](https://colab.research.google.com/) and upload `StreamDiffusion_Colab_Server.ipynb` (or open it directly from Google Drive).
2. Ensure hardware acceleration is set to GPU:
   * **Runtime** $\rightarrow$ **Change runtime type** $\rightarrow$ **Hardware accelerator: GPU** (Select **T4**, **L4**, or **A100**).
3. Click **Runtime** $\rightarrow$ **Run all** (or execute cells 1 through 4 sequentially).
4. Cell 4 will download weights (~2.5GB), warm up the pipeline, start the server, and print your unique WebSocket URL:
   ```text
   🚀 StreamDiffusion Server is READY & STREAMING!
   Copy this URL and paste it into TouchDesigner:
   wss://recorder-thunder-example.trycloudflare.com/ws/stream
   ```

---

### 2. Connect TouchDesigner

1. Open `colab-sd.toe` in TouchDesigner (or drag `StreamDiffusion_Remote.tox` into your own project).
2. Select the **`StreamDiffusion_Remote`** component.
3. In the parameter dialog:
   * **Colab WebSocket URL:** Paste the `wss://.../ws/stream` address from Colab.
   * **Generation Mode:** Choose `Text to Image` or `Image / Noise to Image`.
   * **Input Source:** Choose `External Input (in1)`, `Webcam`, or `Internal Noise`.
   * **Denoise Strength:** Adjust from `0.2` (subtle) to `0.8` (heavy stylization).
   * **Connect to Colab:** Toggle **On**.
4. The output will stream directly into `null1` in real time with live telemetry!

## 🔬 Technical Deep-Dive

### 1. Adaptive "Ping-Pong" Flow Control
Instead of sending frames blindly on a fixed timer, TouchDesigner employs **reactive token flow control**:
* TouchDesigner transmits frame $N$ and sets `can_send = False`.
* Google Colab receives frame $N$, processes through StreamDiffusion ($\sim 75\text{ ms}$), and streams back the output frame.
* TouchDesigner completes receiving frame $N$, displays it on the GPU texture, and immediately resets `can_send = True`.
* On the next frame start, TouchDesigner samples the freshest camera/noise input and transmits frame $N+1$.
* A $250\text{ ms}$ watchdog timer automatically recovers streaming if a packet is ever dropped on the internet.
* A $30\text{ FPS}$ ceiling ($\ge 33\text{ ms}$ spacing) ensures bandwidth efficiency.

### 2. Dynamic Timestep Scheduling (`t_index_list`)
StreamDiffusion uses sparse timesteps for real-time inference:
* **`txt2img`:** `t_index_list=[0, 16, 32, 45]` (4 denoising steps). Produces sharp, coherent images that closely track prompt changes without visual mosaic artifacts.
* **`img2img`:** SD-Turbo has 50 timesteps. The server maps TouchDesigner's `Strength` slider dynamically:
  $$t_0 = \max\left(5, \min\left(44, \text{int}(45 - \text{strength} \times 40)\right)\right), \quad t\_\text{index\_list} = [t_0, 45]$$
  * `Strength = 0.2` $\rightarrow [37, 45]$ (Subtle styling, original composition 90% preserved).
  * `Strength = 0.6` $\rightarrow [21, 45]$ (Balanced hybrid of input contours and prompt generation).
  * `Strength = 0.9` $\rightarrow [9, 45]$ (Heavy AI re-imagination).
  Because the schedule length ($2$ steps) remains constant, update latency is $\le 2\text{ ms}$ with zero GPU memory reallocation!

### 3. Bidirectional Binary Chunking Protocol
TouchDesigner's `WebSocket DAT` relies on POCO C++ and OpenSSL. When transmitting payloads larger than 16 KB over TLS (`wss://`), OpenSSL triggers `SSL_R_BAD_LENGTH` (`1409E10F:ssl3_write_bytes:bad length`) or POCO `Payload too big`.

To solve this, a custom chunking protocol operates in both directions:
* **TouchDesigner $\rightarrow$ Colab (Input Frames):**
  * Sliced into chunks $\le 4096\text{ bytes}$ with a 7-byte binary header:
    $$\text{b'FRM:'} \; (4\text{ bytes}) + \text{frame\_id} \; (1\text{ byte}) + \text{chunk\_idx} \; (1\text{ byte}) + \text{total\_chunks} \; (1\text{ byte})$$
  * Every packet is $\le 4103\text{ bytes}$, well under the 16 KB TLS record limit.
* **Colab $\rightarrow$ TouchDesigner (Output Stream):**
  * Output frames ($512\times 512$) are sliced into 2048-byte chunks with a 3-byte header:
    $$\text{frame\_counter} \; (1\text{ byte}) + \text{chunk\_idx} \; (1\text{ byte}) + \text{total\_chunks} \; (1\text{ byte})$$

## 🛠️ Automated Sync to GitHub

Whenever you want to backup your project:
* On Windows, simply double-click **`sync.bat`**.
* Or from PowerShell/Terminal, run:
  ```powershell
  python sync_to_github.py "Your commit message"
  ```
The script will automatically rebuild `.toe` and `.tox`, update the notebook, stage all files, and push to your private GitHub repo (`wenjunii/colab-sd`). If branch protection is enabled on `main`, the script automatically handles creating and merging a pull request with admin credentials so syncing is completely frictionless.
